Conexões

A varredura lê o que ficou aberto. O valor de token, chave e senha não entra na fila.

  • GitHub {github}
  • AWS {aws}

Como a leitura entra

A Curfew não instala um app no GitHub e não assume uma role. O processo chama a API com o que estiver no ambiente dele.

  1. GitHub. O token fica em CURFEW_GITHUB_TOKEN. A leitura pede os cinco repositórios mais recentemente atualizados que esse token enxerga e, em cada um, metadado de webhook, nome de secret de Actions e chave de deploy.
  2. AWS. O par fica em CURFEW_AWS_ACCESS_KEY_ID e CURFEW_AWS_SECRET_ACCESS_KEY. A chamada é iam:ListAccessKeys no próprio usuário dessa chave. Entram idade, status e quatro finais. As chaves dos outros usuários da conta não entram.
  3. CI. Não há receptor de pipeline. O que aparece de CI são os nomes dos secrets de GitHub Actions nesses cinco repositórios. O valor do secret não entra.
  4. Servidor. As variáveis ficam no ambiente da função ou da máquina. Não vão para o git, a página nem a tabela. Apagar o token e a access key desliga a leitura.

A passagem da noite e a sessão AWS continuam desligadas até um sim separado.
